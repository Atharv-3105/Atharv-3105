About me

Who runs this station, what I care about when I build, and what I'm learning next.

I like building the backend of AI systems more than the AI itself: the ingestion pipelines, the retrieval layer, the service that has to stay up and stay fast.

Most of what I build sits where Go meets Python. Go handles concurrency, I/O and the API; Python handles embeddings, retrieval and model calls. Right now I'm mostly thinking about repository intelligence, RAG infrastructure, and what it takes to run these pipelines reliably at some scale instead of once in a notebook.

I also read papers and rebuild the ideas myself. Writing attention, RoPE or a KV cache by hand is usually the fastest way for me to understand how something works, and that habit is what From_Scratch grew out of.

I finished a B.Tech in AI & ML at AKTU in 2026 and now work as a software developer intern at Helionyex Solutions, on a system that checks and stores climate data from weather stations. Along the way I've mentored 150+ educators in Python and generative AI at NimbleQ, reached the Smart India Hackathon internal finals twice, and solved 600+ problems on LeetCode.

Station rules · how I build

Go for the service, Python for the model
KnowYourRepo, SmartFile Manager and Semantic-Duel all split this way: a Go process owns concurrency and the API, a Python service owns the models.
Let code check what a model can't be trusted with
Graphviz lays out ArchiGen's diagrams, difflib reports JobBot's résumé edits, and plain functions compute financial ratios.
Degrade instead of crashing
Validated multi-provider failover, polling fallbacks when file events go missing, and repair loops when a diagram fails validation.
Measure it, then publish the result
Prometheus and Grafana on KnowYourRepo, and a JobBot test audit that shows the 0/12 run next to the 12/12 fix.
